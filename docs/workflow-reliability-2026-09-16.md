# 操作流程与数据可靠性：第一轮

本轮先完成可靠性修复和日常操作入口，保留现有配色、品牌图片和组件体系。没有数据库迁移，也不修改历史业务记录。

## 行为变化

- 编辑日记仅修改工作内容、地点、时间、标签、优先级。旧客户端即使提交 `isTodo:false`，也不会再删除任务。任务内容、截止日期、状态应通过待办接口修改。
- 新建日记读取日历传入的日期；编辑模式正确显示原优先级。结束时间早于开始时间会被前后端拒绝。
- 地点、标签、优先级收进可展开区域；草稿按账号和记录保存在当前标签页的 sessionStorage，成功提交后清除。刷新/关闭提醒未保存，应用内离开先确认。草稿不跨设备同步，关闭标签页后不保证保留。
- 首页增加记一笔、新增待办、今天记录、逾期及未来七天任务入口；首次使用不再强制填写工作画像，仍可在用户设置中填写。
- 待办支持新增、内容与优先级编辑、调整截止日期、完成/放弃/转交、重新打开、搜索与服务端分页。任务详情编辑不覆盖来源日记；转交仅记录对象，不发送通知。
- 首页通过数据库聚合统计，不再受 1000 条列表上限影响；今天记录按工作发生日期计算，并使用浏览器提供的时区。日历按可见日期范围分页读取。
- 所有总结生成路径查询日记时排除回收站记录；总结翻页请求使用新页码。
- 获取日记详情不再同步写入 Dify；同步移到日记更新后。此轮仍沿用同步调用方式，持久化异步队列另行实现。
- 恢复入口仅接收实际支持的 JSON；上传前检查数据库事务能力，上传后完整校验并预览替换数量，用户确认后执行。上传进度不再冒充恢复进度；取消文件选择不会卡住加载状态。

## 接口

- 新增 `GET /api/diaries/dashboard?timezone=Asia/Shanghai`。
- 新增 `PUT /api/todos/:id`，只接受 content、priority、dueDate。
- 待办列表支持 search、dueBefore、status、page、limit；limit 最大 100，调用方应分页读取。
- `GET /api/backup/status` 增加 restoreAvailable、restoreReason。
- `POST /api/backup/restore` 的 multipart 字段 `dryRun=true` 只校验并返回数量，不恢复、不删除。正式恢复仍使用既有快照和事务实现。

## 验证

后端在独立 MongoDB 副本集中运行 `node --test tests/*.test.js`，28 项通过，无跳过。新增用例覆盖：日记无损编辑、无效时间拒绝、详情读取无外部写入、任务编辑/完成/重新打开、跨用户隔离、分页及统计、1000 条以上统计、删除记录不进入周报、恢复预检不改数据。

前端生产构建通过。仓库仍有ESLint 警告、过期 Browserslist 数据和较大的构建包，本轮未升级依赖或重构打包。

浏览器使用虚构账号和独立数据库验证，不操作生产日记：历史日期传递；新增任务、完成、重新打开和导航计数；关联日记直接保存后任务、截止日期、优先级和标签保持不变；草稿离开后恢复；JSON 备份预览显示正确数量后取消，未执行替换。
